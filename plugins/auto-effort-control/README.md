# auto-effort-control

Reasoning effort for the Claude Code main chat and for the sub-agents it launches. Each main-chat turn starts at a planned level, the model raises or lowers its own with `set_effort`, failing tests raise it, and a cache check keeps every change safe. A sub-agent's effort is set per spawn with a tag, and an agent whose definition opts in with `effortControl` follows its own trouble while it works.

**Main chat.** The turn starts at `planLevel` (`xhigh` for a long prompt or a configured `planUpshiftPatterns` match); the model calls `set_effort` with a level for this turn only, or `auto` to hand the effort back. `hintPatterns` names design and similar words in the reminder without moving the level; `planUpshiftPatterns` defaults to empty. `/effort <level>` pins until `/effort auto` or `/auto-effort-control on`, surviving `/clear`. A bare `/effort` picker choice is inferred from the next turn's carried effort. Two failing test runs in a row lift the level one step and the next passing run returns it. After every change the plugin checks that the prompt cache survived and switches a model off where it did not. `/auto-effort-control` shows, switches off and on, and clears.

**Sub-agents.** Make `[effort: low|medium|high|xhigh|max]` the first non-blank text of the Agent prompt, on one line. The tag is removed before the sub-agent reads its prompt, and its own model requests run at that level. An agent definition with `effortControl: on` is steered: its effort rises at a failing test run or a red sub-task and returns once the trouble resolves, and it can press `effort_up`, `effort_down` and `effort_auto` itself.

It requires function hooks enabled (`CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`) and is tested on Claude Code 2.1.296. Install it with `/plugin marketplace add rezzminator/professor` and `/plugin install auto-effort-control@professor`. Remove it with `claude plugin uninstall auto-effort-control@professor`. It replaces the `auto-effort` and `effort-live-control` plugins and honours or reports their settings; the full documentation, the precedence of every source and the migration notes live in the repository: <https://github.com/rezzminator/auto-effort>

## Options

Set under the plugin's settings, or in the environment variable named in the table. A variable wins over the plugin's setting, which wins over the default; an unset or blank variable counts as not set. Write a boolean as `1`, `0`, `true` or `false` (any case), a list as a JSON array of strings (`[]` is the empty list). `models` and `testCommandPatterns` entries carry their scope, `main:` or `subagent:` (`testCommandPatterns` entries with neither apply to both); a `models` entry with neither is rejected. A bad value is reported by name and the default used. Settings and variables of the retired `auto-effort` and `effort-live-control` plugins are honoured for their scope or reported by old and new key.

## Logs

Error-level diagnostics appear on screen and in `errors.jsonl`. Warnings and routine effort-change diagnostics go only to `warnings.jsonl` and `info.jsonl` under `$PLUGIN_LOG_DIR/auto-effort-control/`, or `$HOME/.local/state/auto-effort-control/logs/` when `PLUGIN_LOG_DIR` is unset. If no log directory resolves or writes fail, every unwritten warning and info message falls back to the screen. The decision logs named by `logFile` are separate: the main chat writes `decisions.<session>.jsonl`, the sub-agents `decisions.<session>.subagent.jsonl`.
